# RULES (enforced by ApplicationYamlRulesTest):
#
#   1. Declare EVERY key here first. Profiles may only override existing keys.
#   2. Do NOT repeat a key in a profile file if its value is unchanged.
#   3. Every key in a profile file MUST be a real override (different value).
#   4. Profile files must NOT introduce new keys — add them here first.
#   5. No duplicate keys within a single YAML file.
#   6. No dead keys here — every key must be either overridden by a profile
#      or referenced in Java code (@Value, @ConfigurationProperties,
#      environment.getProperty). Otherwise delete it.
#
# HOW TO ADD A NEW PROPERTY:
#   1. Add it here with a default value.
#   2. If it differs per environment, override it in application-{profile}.yml.
#   3. Reference it in code — or delete it if unused.
#
# HOW TO OVERRIDE PER ENVIRONMENT:
#   - Override in application-dev.yml / application-test.yml / application-prod.yml
#   - Value MUST differ from base, otherwise R2 fails.
#
# SPRING.CONFIG.IMPORT:
#   - Imported files own their entire subtree — they replace, not merge.
#   - Do NOT declare the same subtree in application.yml and an imported file.
#   - Use "optional:classpath:..." if the file may be absent locally.
#
# RUN VALIDATION:
#   mvn test                    # all rules
#   mvn test -Dtest=ApplicationYamlRulesTest
#
